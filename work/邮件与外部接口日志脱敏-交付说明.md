# 邮件与外部接口日志脱敏

日期：2026-09-15。状态：开发及隔离验证完成，待新版后端加载、数据库迁移及用户验收。

## 本次效果

- 邮件运行日志和投递记录的收件人显示为 `[redacted]`，不保存完整邮箱。SMTP 返回内容可能重复客户邮箱、密码或其他资料，因此仅保留受控的错误类别；运行日志可保留 SMTP 数字错误码。
- 通知邮件的收件人快照单独使用现有 AES-GCM 加密能力保存，字段不参与 JSON 输出。重试使用原收件人，不因客户修改邮箱而改投；成功、最终失败或不再发送后清除该密文。业务联系人资料不变。
- 外部 HTTP 连接器调用日志不再保存请求/响应正文或完整 URL，包括路径、查询参数和片段。非空值统一显示 `[redacted]`，避免漏掉自定义字段、嵌套内容、自由文本和编码后的秘密。
- 日志仍保留公司、连接器、请求方法、HTTP 状态码、耗时、追踪编号和时间。实际接口请求与返回内容不被日志处理改写。
- 外部接口历史日志的读取入口也执行脱敏，并保持原有租户与连接器过滤。

## 历史数据及生效

新增迁移 **142**：为待发送邮件增加独立密文字段，分批处理 `delivery_logs` 的邮件记录和 `access_call_logs`，替换原文但保留日志记录、状态、编号及时间。待重试的历史邮件先加密地址再隐藏原文，终态邮件不保留地址密文；重复执行安全。

本次没有重启用户服务或操作业务数据库。上线时应先停止旧版写入进程，使用既有加密密钥执行迁移 142，再运行新版后端及通知任务，避免旧进程继续写入明文。需要保留原加密密钥以便完成待重试邮件；不要直接回退到不认识密文字段的旧版通知任务。

迁移替换日志原文属于不可逆脱敏；不会删除日志行。历史磁盘日志、外部日志平台和备份不会因数据库迁移自动清除，应按既有保留策略处理，不能据此声称所有历史副本已脱敏。

## 验证

使用 Go 1.26.8、隔离 SQLite、合成数据、本机 SMTP 接收器及无外部网络的 HTTP 模拟传输验证：

- JSON、嵌套资料、坏 JSON、文本、HTML、编码内容和 URL 的原文不进入日志。
- SMTP 成功和拒绝路径的运行日志不包含完整邮箱、密码和邮件正文。
- 真实请求/响应保持完整；接口传输错误及历史读取不暴露敏感内容，其他租户无法读取日志。
- 邮件队列地址加密、JSON 隐藏、失败重试保留原地址、成功清理密文；无效密文不被当作邮箱发送，最终失败清除密文。

- 通知投递/重试、连接器凭据、版本化 SMTP 发信、邮箱设置等定向回归通过；相关包 `go vet` 通过。
