# AI 会话真实流式输出

需求来源：用户本次确认“对话是 AI 的输出不是流式输出，改成流式输出”。未提供对应在线需求行 ID；未修改在线需求状态，也未部署或推送。

## 原因与修改

- Eino Runner 原来关闭 streaming，事件消费者只读取完整 Message；聊天端仅监听最终的 message.created。
- 为实际聊天传入可选的上下文观察器，启用模型 Stream 并逐片读取，推送累计文本快照。没有观察器的调用保留原调用方式。
- 工作流只公开直接绑定到 send_reply 的 LLM 回答；中间分析、ReasoningContent、工具参数和工具返回不作为公开分片发送。工具调用清空该轮临时文本，DryRun 不推送。
- WebSocket 增加 message.streaming，沿用会话与租户路由。分片不入库、不更新未读数；正常提交后继续发送 message.created，以相同 clientMsgId 替换临时消息。
- 工作台、客户网页、客户移动端及客服组件接收快照；过滤重复、过期和旧尝试，保留刷新期间的临时消息，分页和已读游标排除临时 ID。
- 结束、报错、取消、人工接管清理临时文本；对推送进行 40ms 节流，并定时补发末段，避免模型暂停时最后一片滞留。重连同步正式消息。
- 流式调用失败向上返回错误，避免把残缺回答提交为成功；备用模型流保留实际提供方和模型标识，仅在首个分片附加标识以避免 Eino 字符串拼接破坏模型名。

## 本地验证

环境：Windows，Go 1.27.1，Node.js 24.15.0。所有新增测试均使用本地模拟模型、内存/临时测试库；没有调用真实模型或业务数据库。

- 真实模型适配器 + Eino Runner + 本地 SSE：服务端阻塞结束响应，收到首段后才允许结束，验证请求 stream=true，首段没有被缓冲到最后。
- Eino Graph：公开回答首段在工作流完成前到达，最终回答保持完整；非公开节点和 DryRun 不暴露分片。
- 消费者：ReasoningContent/工具内容隐藏，Token 用量保留，流错误不完成残缺回答。
- 推送会话：末段自动刷新，取消、人工接管和关闭前尚无分片时均正确终止。
- WebSocket：会话订阅收到分片，其他租户没有收到，分片不产生数据库消息。
- 前端：12 项消息合并、流式状态及实时会话回归测试通过。
