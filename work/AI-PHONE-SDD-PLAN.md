# AI 电话 Agent SDD 实施计划

## 1. 规格基线

实施以 `work/AI-PHONE-SDD-SPEC.md` 为唯一行为基线。任何接口、字段或流程变更先更新规格，再修改代码。当前已完成 Phase 1 的接口、认证、线路租户绑定和幂等基础实现，以及 Phase 2 的文本 Agent 骨架。

## 2. 实施顺序

### Phase 1：接口和领域契约

- 固定 Python Agent 的状态、动作和上下文结构
- 固定 Go 建单接口、服务认证和幂等行为
- 为 `ai_phone` 或等价来源值确定枚举和配置兼容方案
- 增加 Go 接口的跨租户、重复请求和载荷冲突测试

### Phase 2：Python 本地 Agent

- 实现文本模拟器，不接真实电话
- 实现字段收集、追问上限、客户确认和取消
- 实现 ASR、LLM、TTS 的可替换适配器
- 实现通话状态机和统一错误处理

### Phase 3：Go 建单联调

- Python 调用 Go 测试接口
- 验证成功、超时、结果未知、重复请求和不同载荷冲突
- 验证租户由服务凭证和线路绑定推导
- 验证工单进入现有派单和主管兜底

### Phase 4：FreeSWITCH 媒体接入

- 接通 SIP 测试号码
- 接收 RTP 或 AudioSocket 音频
- 接入 Python 音频输入和 TTS 回注
- 验证客户打断、静音、DTMF、挂机和最长通话时间

### Phase 5：联调和容量验收

- 完成中文、英文和阿拉伯语测试
- 测试多诉求、错听、缺字段和异常断开
- 验证 5 路并发、任务恢复、告警和录音访问
- 记录准确率、P95 延迟、建单成功率、误建率和成本

## 3. 每个阶段的完成定义

- 规格中的接口和状态均有实现或明确的未实现项
- 关键路径有自动化测试
- 失败路径有可观察的错误和恢复结果
- 测试结果记录到交付说明
- 未通过的验收项不能标记为完成
