## 已实现

- 上传状态与扫描状态分开记录；保存 SHA-256、来源、操作者、UTC 时间、引擎和病毒库版本，每次扫描追加记录。
- 现有附件上传、会话媒体、供应商上传、企微接收、知识文档及 FAQ Excel 导入使用统一扫描服务；后续邮件录入可复用，未新增邮件转工单。
- 隔离附件禁止下载、预览、签名 URL、Range 读取、转发和知识入库；RAG 检索过滤尚未通过扫描的源文档。
- ZIP/Office 实际读取展开内容，检查 CRC、加密、大小、数量和嵌套限制；无法可靠展开的 RAR、7z 等归档隔离。
- 私有隔离目录位于普通存储目录之外；扫描和发布使用同一份内容。并发复扫只能有一个执行者，中断超过 15 分钟的扫描由巡检转为隔离。
- 历史附件默认未扫描，需要实际补扫。静态文件、品牌图片和媒体返回前校验扫描状态；部署模板关闭相关代理缓存，旧 ETag 也不能绕过检查。

## 启用步骤

本次未修改业务运行配置、业务数据库，也未部署到业务环境。部署时需要：

1. 启动扫描服务：`docker compose -f deploy/clamav/compose.yml up -d`。确认容器健康、FreshClam 已下载病毒库。使用 1Panel 部署时，更新后的 Compose 已包含该服务和健康依赖。
2. 按 [示例配置](D:/work/helpdesk/config/config.example.yaml) 更新运行配置：开启 `storage.uploadSecurity.enabled` 和 `storage.uploadSecurity.clamav.enabled`，填写扫描地址。本机后端使用 `127.0.0.1:3310`，1Panel 容器内使用 `clamav:3310`。
3. 配置独立、可写且持久保存的 `storage.quarantineRoot`。默认业务上传上限 20 MB、收件硬上限 64 MB、隔离容量 1 GB、病毒库最长允许 7 天；调整大小限制时同步调整 ClamAV 限制。
4. 备份数据库后按项目现有迁移流程执行，例如 `go run ./cmd/server -config config/config.yaml -migrate`，随后更新并重启后端、前端和网关。已有环境继续使用自身的部署绑定配置。
5. 先盘点历史文件，在“历史待补扫”中逐个补扫，未通过前不可使用。对象存储必须同时设置真实私有桶权限和 `private: true`；切换时撤回旧公开权限、清理外部 CDN/代理缓存并处理旧签名链接。已经下载到客户端的副本无法由服务器追回。

1Panel Compose 使用 `!override`，需要 Docker Compose 2.24.4 或以上。ClamAV 采用固定的官方 1.4.3 镜像及摘要，FreshClam 自动更新病毒库，扫描端口只在本机或容器内部使用。

## 最简单的验收方法

在隔离验收环境，用管理员账号进行以下操作：

| 操作 | 应看到的结果 |
|---|---|
| 上传正常文本、PDF、图片或 Office 文件 | 扫描通过后才可下载、预览或入库；扫描记录有真实引擎版本 |
| 上传标准 EICAR 杀毒测试文件 | 提示附件隔离；管理页显示病毒命中；原文件不可下载或转发 |
| 上传损坏/加密 ZIP，或超过配置限制的文件 | 管理页分别显示解压异常或超限，不继续解析 |
| 临时停止验收环境的 ClamAV 后上传正常文件 | 显示扫描失败并隔离；恢复服务后复扫可通过，两次结果都保留 |
| 切换另一个公司账号，查看或调用复扫接口 | 不能读取、复扫其他公司的附件 |
| 访问历史未扫描文件的旧 URL、Range 或带 ETag 的请求 | 不返回附件内容，也不返回允许复用内容的 304 |

**接收不完整的区别：** 超过业务上限但完整收到的文件保留原件；超过收件硬上限、中途断流、临时文件丢失或隔离区已满时，记录“不完整”，不能复扫放行，需要重新上传。HTTP 总大小限制触发时保存拒收事件，不宣称保存完整原件；如果请求先被外部代理拒绝，证据在代理拒收日志，应用无法保存未收到的文件。
