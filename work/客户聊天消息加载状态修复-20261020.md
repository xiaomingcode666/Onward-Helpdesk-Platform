# 客户在线聊天消息加载状态修复

用户反馈：客户在线聊天页面一直显示 Loading messages 和骨架屏。

根因：

- 首次 loadMessages 非静默加载设为 loading；WebSocket 连接后的静默刷新（流式功能接入时新增）、轮询或 focus 刷新更新请求序号，使首次请求失效。静默请求 finally 又因 !silent 条件不清除 loading，造成动画滞留。
- 消息请求完成后还 await 标记已读请求，已读延迟或失败会阻塞/误报消息加载。
- 重复点击当前会话也增加请求序号，但选中 ID 没变化，不触发新的加载，导致在途请求被失效且没有接替请求。

修复：由最新的消息请求统一结束 loading，保留旧请求和跨会话响应过滤；已读改为独立异步请求，失败不影响消息展示；选中同一会话时保留在途请求。
