# REG-001 工程师支持管理：简化需求与设计

日期：2026-09-15。依据用户本轮确认，业务按工程师团队管理，范围为“谁负责、什么时候能联系、处理不了找主管”。

## 重写后的需求

> 系统应登记工程师团队、团队负责人和工程师可接单时间，方便客服找到可处理问题的工程师；工程师无法处理时可转交团队主管，无人接单或接单超时时按现有规则由主管协调处理。

需求分析：客服接到问题后，能看到负责团队、负责人及当前可接单的工程师；问题无法继续处理时，能找到主管协调。

## 简单设计

入口沿用“企业端 → 组织架构 → 工程师团队”，本项目使用现有“技术维护组”。

| 内容 | 设计 |
|---|---|
| 团队与成员 | 沿用现有团队、工程师成员和启用状态。 |
| 负责人 | 每组指定一名主管，由其同时负责团队管理和问题兜底。 |
| 支持时间 | 复用工程师个人可接单时间、时区及请假状态，汇总展示当前可接单人员。 |
| 问题升级 | 工程师无法处理时，通过现有转派操作交给主管；无人接单或接单超时沿用现有兜底规则。未找到可接管主管时明确显示原因。 |

管理员维护配置；客服和工程师按现有权限查看与操作，沿用现有企业数据隔离。

## 复用与少量适配

现有团队、成员、个人可接单时间以及主管兜底逻辑可复用。需要将这些入口统一用于“技术维护组”：当前组织页面仅对非技术根组显示主管选择和可接单时间按钮，团队时间页面的选择列表也主要按产品组筛选。调整页面入口并核对相关接口，让本项目能够直接管理团队和主管。

支持时间继续使用现有个人规则；团队负责人同时承担兜底职责，减少重复配置。

## 用户验收

1. 在“技术维护组”中能查看成员、设置主管并保存，刷新后结果正确。
2. 能查看工程师可接单时间；非工作时间或请假人员不会被显示为当前可接单。
3. 一张测试工单能正常分派；工程师无法处理时能转交主管，无人接单或超时时按现有规则触发主管协调，并有处理记录。
