# TKT-008 邮件回复关联简化版

## 简化目标

客户回复邮件时：

1. 通过 `In-Reply-To`、`References` 和明确的 `[Ticket #工单号]` 线索匹配工单；
2. 唯一匹配时，把邮件写入该工单的邮件往来/进度记录；
3. 无匹配、多个候选、发件人不一致或线索冲突时，保存为 `pending_manual_link`，不自动附加到任何工单；
4. 工作人员选择目标工单后，系统才把邮件写入该工单。

## 已有实现

- `InboundEmail` 保存 Message-ID、In-Reply-To、References、发件人、邮箱、状态和工单 ID。
- 同租户、同收件箱、同 Message-ID 幂等；同 ID 不同正文拒绝。
- 线程头匹配和主题工单号匹配必须通过发件人、租户和收件箱校验。
- 不确定邮件显示为 `pending_manual_link`，不会静默挂到错误工单。
- 新增人工确认接口：

```text
GET  /api/enterprise/v1/notifications/mail-settings/pending-links
POST /api/enterprise/v1/notifications/mail-settings/pending-links/:id/link
Body: {"ticket_id": 123}
```

人工确认后会写入目标工单的 `TicketProgress`，邮件历史接口即可在该工单会话窗口中看到它。

## 验证

```powershell
go test ./internal/services -run '^TestEmail' -count=1
```

覆盖自动建单、正确线程追加、未知线程待人工、发件人/租户/邮箱不一致、冲突线索、重复邮件，以及人工选定工单后的追加。

## 简化边界

- 待人工列表当前提供后端查询和确认接口，尚未增加独立的前端待关联工作台。
- 不使用 AI 猜测归属，不仅凭发件人或相似主题自动挂单。
- 附件、复杂跨邮箱线程合并和批量人工处理不在本次范围。
