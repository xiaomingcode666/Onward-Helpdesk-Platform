# TKT-007 附件病毒扫描与隔离实施计划

日期：2026-09-15。状态：方案规划，尚未开发、部署或验收。

**简化需求**

所有上传或外部渠道接收的附件，只有通过 ClamAV 扫描和文件安全检查后才能使用。发现病毒、超过限制、解压异常或扫描失败时，保存到隔离区，显示原因，禁止下载、预览、发送和知识库解析。

**现有基础与差距**

| 已有 | 需要补齐 |
|---|---|
| 统一附件上传服务、ClamAV TCP 扫描接口 | 强制扫描及 ClamAV、FreshClam 部署配置；本次未核实运行环境是否已启用 |
| 大小、类型、危险文件和 ZIP/Office 检查 | 检查实际解压错误和扫描限额，将各类异常归入隔离 |
| 附件表、上传成功/失败状态 | 独立扫描状态、隔离文件、隔离原因和扫描记录 |
| 下载、预览、消息附件、知识库读取 | 各出口统一检查扫描通过，堵住静态地址和直接生成 URL 的绕过路径 |

当前异常通常在创建附件记录之前直接返回错误，不能查看隔离记录。另有一处需要修正：`failClosed=false` 会忽略扫描错误，其中也包含病毒命中。示例配置的 ClamAV 默认关闭，不能据此推断当前实际运行配置。

**最小实现方案**

复用现有上传入口和同步扫描，按以下五步实施：

1. **启用扫描。** 部署内网 ClamAV 和 FreshClam 自动更新病毒库；检查服务和病毒库是否就绪。入站附件不允许关闭扫描或失败放行。大小、实际解压总量、文件数、嵌套深度、耗时等限制通过配置管理。固定引擎版本，验证超限、加密和格式异常的实际返回行为，不能把引擎跳过检查当成扫描成功。
2. **先存私有暂存区，再决定放行或隔离。** 收件时建立附件记录并分配接收编号，流式写入有容量限制的私有暂存区，计算文件摘要；扫描通过才发布到可用存储。异常文件留在隔离区并记录原因。隔离目录必须位于普通 `/storage` 根目录之外；对象存储采用私有桶或独立私有区域。
3. **所有入口和使用位置接同一规则。** 客户、客服、工程师、供应商、企微和知识文档等现有上传入口统一处理；下载、预览、签名 URL、媒体分段读取、附件转发以及知识库/RAG 解析均要求扫描通过。接口返回隔离编号和原因，不把隔离记录当作可用附件交给下游。企微上传补齐所属租户、会话和来源，不能依靠空用户上下文推断归属。后续邮件录入复用此入口。
4. **增加一个“附件隔离”管理页。** 展示文件名、来源、上传人、时间、隔离原因和扫描结果；沿用现有管理员权限并校验租户范围。管理员可重新扫描，只有复扫通过才能恢复使用。普通上传者看到“附件已隔离”和原因，可重新上传；管理页不提供跳过扫描的放行按钮。
5. **完成故障与真实引擎验收。** 补齐异常分类、隔离存储、访问拦截和入口覆盖测试，再在隔离测试环境连接真实 ClamAV 验证；同时验证服务停止、超时、解压损坏和超限场景。

**状态与最少数据**

主流程：`待扫描 → 扫描通过 / 已隔离`。复扫流程：`已隔离 → 待扫描 → 扫描通过 / 已隔离`。原有上传状态继续表示文件是否存储成功，业务使用须同时满足“存储成功”和“扫描通过”。

在现有附件表增加扫描状态、原因码、SHA-256、私有暂存/隔离位置、来源和接收完整性；复用现有租户、会话、上传人字段。增加轻量扫描记录表，逐次保留扫描时间、引擎和病毒库版本、结果、原因及操作者，时间统一存 UTC。未执行扫描的前置超限等情况如实记录，不伪造引擎结果。

四个主要隔离原因：`infected`（病毒命中）、`limit_exceeded`（超限）、`archive_error`（解压异常或无法解密检查）、`scan_failed`（服务不可用、超时、协议或读取失败）。现有危险类型拦截另记 `policy_blocked`，避免全部显示成“发现病毒”。

**实现时必须处理的边界**

- ZIP/Office 检查不能只信目录中声明的大小，要在资源限制内实际读取并检查展开错误、校验失败及嵌套内容；未支持或无法完整检查的归档进入隔离。
- 区分可用附件大小限制和收件硬上限。完整收到的超限文件保留原件并隔离；超过收件硬上限或中途断流时停止接收，记录隔离事件、已收字节和“不完整”，不能把截断内容当作完整文件复扫放行。反向代理提前拒绝的请求也要有可关联的拒收记录。验收需区分“原件已隔离”和“未完整接收”，单纯返回 413 不算原件隔离完成。
- 扫描和最终发布使用同一份不可变内容；状态持久化失败不得发布文件。进程中断留下的待扫描记录通过轻量巡检转为扫描失败并隔离；并发复扫只能有一个执行者，复扫不重复创建业务附件。隔离空间不足时停止接收并保留失败事件，不能标记为已保存原件。
- 历史附件不得批量标成已扫描。切换前先盘点、补扫，再启用访问限制；尚未补扫的文件保持不可用。旧静态 URL、已签发链接和存储公开权限必须纳入切换，避免只改 API 后原地址仍可访问。实际迁移作为实施步骤，不在本次规划中操作历史数据。

**如何验收**

| 测试 | 通过标准 |
|---|---|
| 正常 PDF、图片、Office 和允许的压缩包 | 有真实 ClamAV 扫描成功记录，之后才可使用 |
| EICAR 测试文件 | 进入隔离，有明确原因，无业务可用 URL；另提供真实引擎命中证据，不能只依赖现有本地 EICAR 字符串拦截 |
| 文件大小、解压总量、数量或嵌套超限 | 进入隔离并显示超限；覆盖应用限制与 ClamAV 内部限制 |
| 损坏、加密、解压校验失败的压缩包 | 进入隔离，不继续文档解析或知识入库 |
| ClamAV 停机、超时、断连、病毒库未就绪 | 进入隔离，不能因配置或异常处理而放行 |
| 访问绕过和归属 | 待扫描/隔离附件无法通过旧 URL、签名接口、预览、Range 或附件转发读取；其他租户不能查看记录或复扫 |
| 复扫与故障恢复 | 复扫通过才可用，每次结果保留；中断和并发不会产生提前放行或重复业务附件 |
