# FUN-053 / FUN-054 低置信度与敏感意图升级策略

日期：2026-09-22。状态：本轮实用功能开发完成，已完成本地 AI 回归，待用户验收；线上需求表状态待同步。

## 需求简化

基础版只保留四条运行时硬规则：

1. 用户明确要求人工，立即转人工。
2. 命中退款、赔付、账户、封禁、Priority 最终裁决等敏感意图，立即转人工。
3. 知识检索低置信度或不可回答时，具备人工能力的流程立即转人工。
4. AI-only 流程不能转人工时，返回能力边界兜底，不继续假装完成升级。

现有 Agent Release/Workflow 的发布、审批、部署、回滚和运行快照能力继续复用。本轮没有新增六类独立配置版本快照，也没有新增连续失败持久化计数。

## 对应现有功能

- Agent Release 审批与回滚：`internal/services/ai_agent_release_service.go`
- Workflow 版本与回滚：`internal/services/ai_workflow_service.go`
- 敏感意图分析：`internal/ai/runtime/graphs/analyze_conversation_graph.go`
- 低置信度判断：`internal/ai/runtime/workflow/executor.go` 的 `answerability_gate` 和 `reply_policy`
- 默认售后流程升级分支：`internal/ai/workflow/builtin/manifests/01-aftersales-customer-service-default.json`

## 本轮修改

- `AnalyzeConversationGraph` 新增 `sensitive_intent` 风险信号，命中后推荐 `handoff_to_human`。
- 默认售后工作流的低置信度分支从 AI 安全收口改为转人工。
- `reply_policy` 对 `answerability != answerable` 的结果，在流程具备人工能力时强制转人工。
- AI-only 流程继续返回知识兜底。

## 后续修改建议

- 增加会话级连续失败计数，例如连续 2 次低置信度或模型失败后强制转人工，并写入审计事件。
- 将 Content、Intent、Flow、Fallback 阈值、Sensitive Intent、Escalation Policy 固定写入 Agent Release 快照，发布前逐项审批，回滚时恢复同一快照。
- 为敏感意图和升级阈值增加管理员可见的版本差异与验收记录。
