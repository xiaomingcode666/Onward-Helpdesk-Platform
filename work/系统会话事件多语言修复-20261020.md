# 系统会话事件多语言修复（2026-10-20）

本次按用户“找到原因，从源头解决”的要求修复工单创建、供应商邀请和加入协作事件。

## 根因

- 事件生产者直接拼接中文系统消息，消息服务原样生成持久化摘要。
- 工作台 API 原样返回摘要，常规会话 API 只处理少量媒体和撤回文案。
- WebSocket 原样广播正文和摘要，前端收到消息后又用正文重建摘要，页面级补丁容易被覆盖。

## 改动

- 复用 `i18nx.Text`，以已知 `eventType` 和业务参数生成正文、摘要资源 key。
- 移除上述事件生产者的中文拼接。消息服务在现有 Payload 内保存 `systemText`；兼容消费者仍可读取渲染后的 Content。
- 历史事件根据已有元数据在读取时恢复翻译信息，不改写业务记录，无需数据库结构迁移。
- 会话列表、详情、工作台和客户门户返回按请求语言渲染的摘要及可重新渲染的 key/参数。列表批量读取末条消息，校验消息与会话归属。
- WebSocket 按每个连接的语言渲染正文和摘要，同时保留 key/参数供浏览器切换语言。
- 前端缓存、API 适配和实时更新保留结构化信息；新客户消息及撤回操作清除旧的系统摘要信息。
- 仅识别系统发送者的已知文本事件；客户、工程师和 AI 原文及公司/模块等业务参数保持原文。撤回状态优先于旧事件。

前端上述 15 个测试通过，覆盖历史记录、真实消息渲染/实时状态更新、语言切换和客户原文保留。变更前端文件 ESLint 无错误，相关页面/API 文件存在 19 条既有警告；核心摘要、消息、实时状态和 store 文件无警告。

另运行 `web/app/enterprise/ticket-workbench/ticket-workbench-language.test.mjs` 时，有一条既有测试失败：它要求源码直接包含中文“译文”，当前页面使用资源 key。已读取 HEAD 同一源码确认基线也不匹配该断言，未修改或跳过该测试。
