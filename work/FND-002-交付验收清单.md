## 用户现在可以做什么

公司管理员打开“企业工单 → 新建工单 → 受理规则齿轮”，点击“载入现有运营设置（升级配置）”。之后统一走“修改 → 保存草稿 → 检查 → 应用”。生产和预发布环境最后一步是导出，由工程师通过已有部署命令应用。

| 功能 | 现在的行为 | 验证证据 |
|---|---|---|
| 配置版本 | 保存草稿不改变正在使用的设置；每次应用记录内容、操作人、时间与摘要 | 配置生命周期、幂等及冲突测试 |
| 部署前检查 | 检查格式、设置间关系、公司/环境和真实密钥文件；不通过就拒绝应用 | Schema/Policy/Secret 及部署命令回归 |
| 公司设置 | 语言、时区、设备售后/知识服务模式随版本生效；服务模式切换保留原组织初始化逻辑 | 运行字段恢复及服务模式完整迁移库测试 |
| 日历和 SLA | 可配置工作日、上下班、休息日期及首次回复/接单/解决时限；新工单记住当时版本 | 时间边界、旧目标继续执行、接单截止时间测试 |
| 工单来源 | 未启用来源被创建服务拒绝；开启不会自动建立第三方账号或连接 | 禁用 email 创建被拒绝测试 |
| 邮件发送 | 发信人、SMTP、回复地址、密码引用、重试设置随版本使用；关闭后不偷用平台邮箱 | 本机 SMTP 实际接收测试、密钥缺失与开关测试 |
| 外部接入 | 地址、应用编号、凭据引用及附加设置纳管；旧接入管理入口不能绕过版本写入 | 配置校验、迁移保护和受管写入口 |
| 保存策略 | 现有清理任务按公司配置运行；证据保留开启时停止自动清理该公司 | 临时库保留/解除保留、全局审计隔离测试 |
| 自动关闭 | 等待天数及开关随版本生效；沿用既有例外和关闭流程 | 自动关闭回归 |
| 恢复旧设置 | 将历史内容另存新版本再应用；不删除旧记录、不伪造历史工单版本 | 事务回滚、恢复及迁移测试 |
| 权限 | 运营配置仅公司所有者/管理员或已有公司管理权限账号可写 | 普通工程师拒绝测试 |

## 人工验收顺序

1. 在测试公司载入设置，确认时区、语言、邮箱、日历与当前业务一致。密钥只填写工程师提供的 `secret://名称`。
2. 改一个明显的设置，例如默认时区；保存草稿后重新查看正在使用的配置，确认尚未变化。
3. 故意填一个不存在的日历引用或错误时区，点击检查，确认失败并有说明；修正后再应用。
4. 设置工作日 09:00–18:00，给某个工单优先级设置解决时限。新建测试工单并查看版本与截止时间。再修改该时限，新建第二张工单；第一张应继续按原版本处理。
5. 载入曾经生效的 v2 内容，另存、检查、应用；确认公司设置一起恢复。载入没有运营设置的 v1 历史时，页面会保留当前运营设置及其实际依赖的密钥引用；检查邮箱、外部接入共用密钥时，修改其中一处不会删除另一处仍在使用的引用。
6. 尝试从旧邮箱/SLA/保存策略页面直接修改，确认系统要求使用配置版本管理。
7. 在获准的目标预发布环境准备密钥和配置包，执行部署检查、应用、重启及恢复演练。真实发信测试需使用获准的测试收件地址。

## 必须区分的边界

- 配置功能完成不等于所有独立业务需求完成。这里没有新增完整 WhatsApp、GLPI/Chatwoot 适配器，也没有把系统拆成原文的独立项目部署架构。
- 保存策略当前覆盖已有清理任务，不等于附件、备份、指标等所有数据已具备完整 DAT 分类治理。地区标记不会搬迁数据库。
- 时限使用现有工单优先级，不等于已经完成 TKT-005 的 P1–P4 语义改造；工程师每次派单的接单窗口仍是既有派单策略，配置 SLA 是从工单创建开始的整体接单目标。
- 旧 v1 配置没有记录运营设置；不能恢复它从未保存过的历史。已纳管的新工单使用固定版本，未记录版本的旧工单保持原有兼容处理。
- 真实公司数据、外部账号、生产环境本次未改动。可以进行功能交付验收，尚不能填写“生产验收已通过”。
